Chapter 1 ・ 官方資安文件

🛡️ 開支索償與收支管理系統
系統架構、資安防禦與安心使用白皮書

致全體團隊成員與夥伴：
為了讓大家在進行日常開支報銷、單據核對與財務管理時更加高效、透明且享有最高規格的隱私保障，我們正式啟用了本套專屬管理系統。本文件旨在公開系統的底層架構、前後端防禦邏輯及隱私隔離機制。

🏛️ 一、 基礎設施：Google Firebase 全球企業級雲端服務

本系統並非架設於隨時面臨單點故障或漏洞風險的傳統主機，而是完全基於 Google Cloud Platform (GCP) 旗下的 Google Firebase 伺服器端無伺服器（Serverless）架構，具備與跨國金融機構同等級別的安全標準：

  • 傳輸層安全協議（TLS 1.3 / HTTPS 256-bit 加密）： 所有通訊均受全鏈路高強度加密保護，徹底杜絕中間人攻擊（MITM）。
  • 密碼學身分鑑別（Firebase Authentication & JWT）： 使用者每次登入由 Google Auth 進行身分校驗，無法偽造。
  • 分散式高可用資料庫（Cloud Firestore）： 資料具備多資料中心異地即時備份，具備 99.999% 服務可用性。
  • 二進位儲存槽與存取控制（Firebase Cloud Storage）： 收據圖片獨立存放，受 ACL 安全規則管控。

🔒 二、 專屬邀請暗號機制（封閉式團體專用門禁）

  • 非公開註冊模式： 全面關閉公開註冊，新成員必須取得專屬邀請暗號方可註冊。
  • 防暴力窮舉與防拖庫： 伺服器端關閉批量讀取權限，僅允許單筆精準比對。
  • 配額鎖定與原子計數： 每個邀請暗號設有使用上限，額滿自動失效。

🛡️ 三、 前後端防禦縱深與 F12 防禦邏輯

【防禦審計對照表 (Server-Side Enforcement)】 【攻擊者客戶端嘗試 (F12 / API)】 【Google 伺服器端規則審計】 【結果】 1. 傳送 payload 將 role 改為 'admin' ──➔ 檢查: request.resource.data.role == 'member' ──➔ ❌ 403 拒絕提權 2. 發起 Update 請求修改單據金額 ──────➔ 檢查: allow update: if isSuperAdmin() ──➔ ❌ 403 禁止修改 3. 嘗試讀取非本人 UID 的收據圖檔 ────➔ 檢查: request.auth.uid == userId ──➔ ❌ 403 阻斷讀取 4. 在輸入欄位夾帶 XSS 惡意腳本 ────────➔ 前端: escapeHtml() 轉義為純文字實體編碼 ──➔ 🛡️ 腳本失效

📋 四、 全體成員安心承諾清單

核心關切事項 系統技術保障機制
我的收據隱私會外洩給其他會員嗎？ 🔒 絕對不會。由 Firebase Storage 依據專屬 UID 進行物理隔離。
已提交的帳目會被他人暗中修改嗎？ 🔒 絕對不會。一般會員無資料庫 Update 權限，單據不可篡改。
