Chapter 2 ・ 進階 Web 攻防與資安剖析

超越 F12：Web 潛在破解手法
與 Firebase 極速制止（Fast Blocking）機制

超越前端工具的資安視野：
在真實的網路攻防中，黑客除了按鍵盤 F12 開發者工具外，還會嘗試從傳輸層、身分鑑別層、API 介面、依賴套件等多個維度發起攻擊。
本章節將深度剖析除了 F12 以外的 5 大進階破解手法，並詳細說明 Google Firebase 底層是如何在毫秒級（Fast-Block）時間內將這些惡意意圖徹底阻斷！

🎯 一、 繞過前端，直接對 API 發起請求（API Bypassing）

黑客攻擊手法：繞過 UI 邏輯構造 HTTP 封包 威脅等級：高

黑客不使用瀏覽器 UI，而是利用 Postman、cURL 或自訂腳本，繞過前端輸入框與按鈕限制，直接將數據封包發送給 Firestore 或 Storage API。

⚡ Firebase 極速制止與防禦原理（Why & How）：
  • 為什麼能秒殺？ 因為 Firebase 採用「Server-Side Rules 零信任」驗證，根本不相信前端傳來的任何資料。
  • 如何秒殺？ Firestore Rules 在 Google 伺服器入口處強制執行 allow update: if isSuperAdmin() 與 request.resource.data.role == 'member'，封包抵達 Google 伺服期的 0.01 秒內即被丟棄並拋出 403 錯誤，連資料庫的邊都碰不到！

🔑 二、 認證與 Token 竊取 / 洩漏（Auth & Session Hijacking）

黑客攻擊手法：獲取合法使用者的身分憑證 威脅等級：高

黑客嘗試竊取合法使用者的 JWT Token / Session，進行身份冒用、XSS 腳本注入或中間人截取。

⚡ Firebase 極速制止與防禦原理（Why & How）：
  • 為什麼能秒殺？ 採用 TLS 1.3 軍規加密 + 密碼學數位簽章 JWT Token。
  • 如何秒殺？ 前端全面經由 escapeHtml() 進行動態消毒，XSS 惡意腳本無法執行；傳輸全程加密防範中間人竊聽。即使黑客拿到 Token，Google Auth 也會實施動態過期與簽章校驗，假憑證即刻失效！

💣 三、 邀請碼自動化窮舉（Brute-Force & Enumeration）

黑客攻擊手法：自動化腳本撞擊邀請暗號 威脅等級：中

黑客撰寫 Bot 自動化腳本，以每秒數百次的速度發起註冊請求，試圖「撞出」正確的邀請碼。

⚡ Firebase 極速制止與防禦原理（Why & How）：
  • 為什麼能秒殺？ 結合 Anti-Enumeration 規則 + App Check 設備指紋驗證。
  • 如何秒殺？ 關閉 allow list: 權限，黑客無法批量抓取；App Check 配合 reCAPTCHA v3 在第一時間識別出「非人操作」的自動化腳本，直接拒絕 API 響應，連密碼比對的機會都不給！

📦 四、 前端第三方函式庫供應鏈漏洞（Supply Chain Vulnerability）

黑客攻擊手法：利用第三方 CDN 舊套件漏洞 威脅等級：中

黑客試圖透過污染第三方 CDN 函式庫（如 SheetJS / JSZip），利用解析特製檔案來引發記憶體溢出。

⚡ Firebase 極速制止與防禦原理（Why & How）：
  • 為什麼能秒殺？ 官方可信 CDN 託管 + 隔離環境運行。
  • 如何秒殺？ 嚴格選用 cdnjs 官方憑證節點，搭配 Subresource Integrity (SRI) 雜湊校驗，一旦 CDN 檔案有 1 個 Byte 被竄改，瀏覽器會立即拒絕載入該 JS 檔案！

🚨 五、 邏輯漏洞與資產濫用（Denial of Service / Storage Exhaustion）

黑客攻擊手法：合規帳號上傳巨量檔案耗盡資源 威脅等級：中

惡意使用者註冊後，持續上傳 9.9MB 大圖，試圖塞爆 Storage 儲存空間。

⚡ Firebase 極速制止與防禦原理（Why & How）：
  • 為什麼能秒殺？ Storage Rules 規格鎖定 + 配額告警。
  • 如何秒殺？ 伺服器規則限制單檔大於 10MB 或非 image/* 格式立刻拒絕上傳；後端 GCP Budget Alerts 即時監控配額，防範資源被惡意耗盡！
